# 麦麦时光机 · MCD Time Machine

> 把麦当劳历史订单变成一条可以回溯的时间线。

## 这个 Skill 解决什么问题

麦当劳 MCP 的 35个工具里，`order-list` / `query-order` 只解决「查得到」，
但没人告诉你**这些数据合起来意味着什么**。本 Skill 把订单流水变成三样东西：

| 用户问法 | 能力 | 产出 |
|---|---|---|
| 「我这些年都吃了什么？」 | 消费时间轴 | 按月/渠道/门店/时段切片，标出深夜单、早餐单、最长空窗期 |
| 「我是怎样的麦麦用户？」 | 口味画像 | 一句话结论 + 画像标签 + 常点TOP8 + 均价/中位数 |
| 「把去年那顿再来一次」 | 订单复刻 | 定位那一单的完整清单 + 复刻提示，绝不自动下单 |

## 调用链路

```
用户提问
   │
   ├─ 第一步：now-time-info          确认当前时间（"上个月""最近"等相对表述需要）
   ├─ 第二步：order-list             拉取历史订单流水
   │        └─ 分页拉取直到取完或达到用户要求的时间范围
   ├─ 第三步：本地分析（离线）        build_timeline / build_taste_profile / rank_moments
   │        └─ 用 src/mcd_time_machine/ 的引擎，不联网
   └─ 第四步（仅复刻场景）：query-order → query-meal-detail → query-meals
            └─ 复刻含套餐时，逐个 query-meal-detail 查可替换项
            └─ 用 calculate-price 复核现价
            └─ 【必须】用户确认后才可 create-order
```

## 三个必须遵守的硬规则

### 1. 绝不自动下单
本 Skill 的复刻能力只输出**清单和建议**。即使历史上这一单一模一样，
也必须走完整链路并经用户明确确认，才可调用 `create-order`。

```
❌ "好的，已经帮你复刻并下单了"
✅ "这是2025-03-02 那单的清单：巨无霸套餐×2，原价 ¥84。
    当前门店同款售价 ¥84，可用券『9.9元购品』1张，实付预估 ¥74.1。
    要我现在下单吗？"
```

### 2. 缺数据时降级，不要编
`order-list` 可能返回空列表（新人用户）、或部分订单缺时间戳。
处理规则：

- 返回空 → 直接告诉用户「还没有历史订单记录」，不要用 `query-meals` 编造一份
- 部分缺时间戳 → 这些订单**保留**用于口味画像（菜品和金额仍有效），
  但**不计入**时间轴；在回复里说明"N 单因缺时间未纳入时间轴"
- 字段读不到 → 用 `references/tools.md` 里的容错别名表排查，不要臆测字段名

### 3. 数据只留在本地
订单流水、积分、地址均为用户隐私。
- 所有分析在本地完成，不上传任何第三方
- 回复中**不复述完整地址和电话**，需要时只说「已用默认地址」
- 截图/日志/README 中不得出现真实订单号、门店全称+门牌号组合

## 指令词速查

| 用户说 | 怎么做 |
|---|---|
| 看看我的麦麦时间轴 / 我都吃了啥 | `build_timeline`，输出按月折线 + 深夜单占比 |
| 我是什么风格的麦麦用户 | `build_taste_profile`，先给 headline 再给 traits |
| 上次我点的什么 | `order-list` 取最近一单 → `query-order` 补明细 → 复刻清单 |
| 把 2025-11-11 那单再来一次 | `replay_order(when="2025-11-11")` → 走第四步链路 |
| 随机来一口 / 回忆一下 | `rank_moments`，优先推深夜高客单那几单（故事性最强） |
| 我多久没吃麦当劳了 | 时间轴的 `longest_gap_days` + 最后一单日期 |
| 我最爱哪家店 | 时间轴的 `by_store` 第一名 |

## 表情输出建议

按用户画像的调性选择，不要每句都堆emoji：

```
时间轴  → 📅 2026-10 · 6单 · ¥412
口味画像 → 🍟 深夜食客 / 套餐信徒 / 回头客
复刻    → ⏱ 回到 2025-03-02
```

## 常见追问的应对

**Q：我一年花了多少？**
用 `build_timeline.total_orders` ×各单 `total_amount` 求和。
注意区分「实付」与「原价」——若出参同时有 `discountAmount`，
两个口径都要报，并说清是哪个。

**Q：能帮我取消那笔订单吗？**
这是 MCP 能力（`cancel-order`），不属于本 Skill 的复刻范畴。
可以帮用户查（`query-order` 确认状态），但取消动作必须让用户自己确认后再执行。

**Q：历史订单里有别人一起点的吗？**
`order-list` 是账号维度的流水，同账号即同一用户。
若用户想按「谁点的」拆分，MCP 不提供该粒度，直说做不到，不要编。
